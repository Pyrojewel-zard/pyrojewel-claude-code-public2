# Digital Import Flow — Innovus → Virtuoso

How to import a digital block (GDS + flat Verilog) into a Virtuoso OA library so that:

- **layout** view contains the placed/routed geometry.
- **schematic** view contains the top cell with all stdcells as **pure references** to the standard-cell library (no leaf cellviews duplicated into the target library).
- **symbol** view auto-generated by ihdl.

Empirically validated on SMIC110 with `scc011ums_uhd_rvt`, four designs imported into a shared `SIPO_0621` library (SIPO V8, SIPO V9Demo, PISO V4, PISO V4Demo).

The wrapper at `examples/01_virtuoso/digital_import/import_smic110_sipo.py` works for V8-style inputs but **fails silently on different Innovus exports** — read this file before reusing it on a new design.

---

## TL;DR — when it "just works"

```bash
# 1. Verify source files on remote
ssh "$VB_REMOTE_HOST" "ls <innovus_output>/*.gds <innovus_output>/*_apr_flat.v"

# 2. Ensure target lib registered in cds.lib (one-time)
ssh "$VB_REMOTE_HOST" "grep <TARGET_LIB> <workdir>/cds.lib"

# 3. Generate clean verilog (top-only, no stdcell stubs)
# 4. (Conditional) Strip .VPW/.VNW connections — see "VPW/VNW gotcha" below
# 5. Import GDS
python examples/01_virtuoso/digital_import/import_gds.py <gds> \
    --target-lib <TARGET_LIB> --tech-lib <TECH_LIB> --cell <TOP>

# 6. Import clean verilog
python examples/01_virtuoso/digital_import/import_verilog.py <clean.v> \
    --target-lib <TARGET_LIB> --ref-libs <STDCELL_LIB> \
    --power-net <VDD_NET> --ground-net <VSS_NET> --cell <TOP> \
    --structural-views schematic_and_functional

# 7. Postcheck
```

## Pre-flight: read the actual netlist

Three things vary across Innovus exports and **must be inspected**, never assumed:

### A. Is the top really flat?

A file named `*_apr_flat.v` can still contain a hierarchical top with intermediate modules. Check whether the top module instantiates stdcells directly:

```bash
# UHDV is scc011ums_uhd_rvt's marker; substitute your lib's marker
ssh "$VB_REMOTE_HOST" "awk '/^module <TOP> /{f=1} f && /^endmodule/{exit} f' <flat_v> \
  | grep -oE '[A-Za-z0-9]+UHDV[A-Za-z0-9]*' | head -2"
```

If the top instantiates `sipo_top u_core (...)` instead of stdcells, you have a **hierarchical "flat"** — pick the truly flattened export, or accept a multi-level schematic. SIPO V8 ships both `sipo_top_flat_apr.v` (hierarchical, kept `u_core`) and `sipo_top_flat_apr_flat.v` (real flat). The first one's leaf instances will collapse to `instances=0` in the schematic.

### B. Does the top instantiation include VPW/VNW?

Innovus' `-includePowerGround` emits four power ports on stdcell **module declarations**: `VSS, VPW, VNW, VDD`. Whether the top **instantiates** them with all four depends on the export script:

```bash
ssh "$VB_REMOTE_HOST" "awk '/^module <TOP> /{f=1} f && /^endmodule/{exit} f' <flat_v> \
  | grep -oE '\.(VPW|VNW|VDD|VSS)\([^)]*\)' | sort | uniq -c"
```

- **`.VPW(VSS) .VNW(VDD) .VDD(VDD) .VSS(VSS)` (4 lines each)** — SIPO V8 / V9Demo style. Library `scc011ums_uhd_rvt` symbols only have `VDD/VSS` terminals; the extra `.VPW`/`.VNW` pin mismatch makes ihdl **abandon pure reference and create local cellviews**. You MUST strip `.VPW`/`.VNW` lines from the netlist before import.
- **`.VDD(VDD) .VSS(VSS)` only (2 lines each)** — PISO V4 / V4Demo style. Top instantiation is already clean; no stripping needed.

This is *the* deciding factor between "30 lines of preprocessing" and "just run it".

### C. Does the top module port list include VDD/VSS?

```bash
ssh "$VB_REMOTE_HOST" "sed -n '/^module <TOP> /,/);/p' <flat_v> | grep -wE 'VDD|VSS'"
```

If yes: ihdl will create top-level `VDD`/`VSS` schematic pins. If no: VDD/VSS become **internal nets**, and the global-net handling (`-power-net VDD -ground-net VSS`) is the only thing that gives them sigType `power`/`ground`.

## Pre-flight: standard-cell symbol terminals

The ref-lib symbols' terminal names must match the top instantiation pins. Verify once per PDK, cache the answer:

```python
# scc011ums_uhd_rvt symbols carry only signal + VDD + VSS terminals (no VPW/VNW)
sk = ('let((cv) cv=dbOpenCellViewByType("scc011ums_uhd_rvt" "BUFUHDV1" "symbol" nil "r") '
      'sprintf(nil "%L" cv~>terminals~>name))')
# => "(\"Z\" \"VDD\" \"VSS\" \"I\")"
```

If your library uses different power-pin names (e.g. `VPWR/VGND` in TSMC FreePDK), the strip step targets different lines.

> **SKILL pitfall**: do NOT use `t` as a loop variable in `setof`/`foreach`. It's the SKILL boolean `true` and triggers `Variable is protected and cannot be assigned to`. Use `tm`, `inst`, etc.

## Step-by-step

### 1 — Verify source files exist

```bash
ssh "$VB_REMOTE_HOST" "ls -la <innovus_out>/{*.gds,*_apr_flat.v,*_apr.sdf}"
```

The `.sdf` is for post-import gate-level simulation; it is **not** imported into Virtuoso — it's referenced by the simulator at run time.

### 2 — Ensure target library is registered

```bash
ssh "$VB_REMOTE_HOST" "grep -E '^DEFINE <TARGET_LIB> ' <workdir>/cds.lib"
```

If absent, create the library directory and append the DEFINE line:

```bash
ssh "$VB_REMOTE_HOST" '
LIBDIR=<workdir>/<TARGET_LIB>
mkdir -p "$LIBDIR"
# Copy cdsinfo.tag from an existing library
cp <workdir>/<existing_lib>/cdsinfo.tag "$LIBDIR/"
echo "DEFINE <TARGET_LIB> $LIBDIR" >> <workdir>/cds.lib
'
```

Then refresh the daemon: `client.execute_skill('ddUpdateLibList()')`.

### 3 — Generate clean verilog (top-only)

ihdl scans **all** module declarations in the file. Leaving stdcell module stubs in causes ihdl to (a) waste time on them and (b) on power-pin mismatch, populate them as local cellviews in the target lib. Solution: pass only the top module.

```bash
ssh "$VB_REMOTE_HOST" '
SRC=<innovus_out>/<TOP>_apr_flat.v
DST=<workdir>/<TOP>_clean.v
awk "/^module <TOP> /{f=1} f{print} f && /^endmodule/{f=0}" "$SRC" > "$DST"
grep -c "^module " "$DST"   # should print 1
'
```

### 4 — (Conditional) Strip .VPW/.VNW instance connections

Run only if pre-flight B detected VPW/VNW connections:

```bash
ssh "$VB_REMOTE_HOST" '
SRC=<workdir>/<TOP>_clean.v
DST=<workdir>/<TOP>_clean.v.tmp
sed -E "/^[[:space:]]*\.(VPW|VNW)\([^)]*\),?[[:space:]]*\$/d" "$SRC" > "$DST"
mv "$DST" "$SRC"
grep -cE "\.(VPW|VNW)\(" "$SRC"   # should print 0
'
```

The remaining instantiation reads `.I(...), .Z(...), .VSS(VSS), .VDD(VDD))` — comma-separated with terminating `)`. Trailing-comma syntax stays valid because `.VSS` keeps its trailing comma and `.VDD` was the last field.

### 5 — Import GDS

```bash
python examples/01_virtuoso/digital_import/import_gds.py \
    <innovus_out>/<TOP>.gds \
    --target-lib <TARGET_LIB> \
    --tech-lib <TECH_LIB> \
    --cell <TOP>
```

Even with `import_lib_cells=0` semantics on the schematic side, strmIn **always** materializes every cell present in the GDS as a `layout` cellview in the target library. That's not duplication — flat layout is geometrically composed of those leaf cells; they have no schematic/symbol view, so the schematic stays pure-reference.

Expected output: `[OK] <TARGET_LIB>/<TOP>/layout: instances=<N> shapes=<M> bbox=<BB>`.

### 6 — Import clean verilog

```bash
VB_PROFILE=<profile> python examples/01_virtuoso/digital_import/import_verilog.py \
    <clean.v's basename> \
    --target-lib <TARGET_LIB> \
    --ref-libs <STDCELL_LIB> \
    --power-net <VDD_NET> \
    --ground-net <VSS_NET> \
    --cell <TOP> \
    --structural-views schematic_and_functional
```

**Caveats:**

- ihdl runs in Virtuoso's workdir as cwd, so the verilog filename is resolved **relative to workdir**. Pass a basename if the file is already there; pass an absolute local path and the wrapper will stage it (upload) first.
- ihdl is launched via SKILL `system()` from the daemon and **detaches**. Expect the wrapper to print `system() returned ''` and exit non-zero. This is **not a failure** — poll with `ssh "$VB_REMOTE_HOST" "pgrep -u <user> -f 'ihdl.*<TOP>'"` until it disappears. For a `<TOP>` with ~25k stdcell instances, ihdl takes ~5–10 min; for ~2k, ~30 s.
- Tail `<workdir>/verilogIn.batch.log` to confirm. The **pure-reference success marker** is many lines of:
  ```
  INFO (VERILOGIN-126): Unable to find the Verilog definition for module <CELL>.
      Therefore using library <STDCELL_LIB>, cell <CELL>, and view symbol as the symbol.
  ```
  If you instead see `Checked-in schematic <CELL>` for every stdcell, your `--ref-libs` symbol terminals don't match the instantiation pins (you skipped step 4 or the lib uses different power names).
- `--power-net VDDD` / `--ground-net VSSS` is the V8-era default in the wrapper and is **wrong for V9Demo and PISO V4/V4Demo** — modern exports use `VDD/VSS`. Always pass `--power-net` / `--ground-net` explicitly to match the net names in the verilog instantiation `.VDD(<here>)`.

### 7 — Postcheck

```python
sk = (f'let((lc sc syc) '
      f'lc=dbOpenCellViewByType("<TARGET_LIB>" "<TOP>" "layout" nil "r") '
      f'sc=dbOpenCellViewByType("<TARGET_LIB>" "<TOP>" "schematic" nil "r") '
      f'syc=dbOpenCellViewByType("<TARGET_LIB>" "<TOP>" "symbol" nil "r") '
      f'sprintf(nil "layout=%s sch=%s sym=%s sch_inst=%d sch_terms=%d" '
      f'  if(lc "Y" "N") if(sc "Y" "N") if(syc "Y" "N") '
      f'  if(sc length(sc~>instances) 0) if(sc length(sc~>terminals) 0)))')

# Pure-reference audit: dump each instance's libName, count how many point to STDCELL_LIB.
# (Don't try to print the list via SKILL — it truncates. Write to /tmp and analyze offline.)
sk_audit = ('let((cv p) cv=dbOpenCellViewByType("<TARGET_LIB>" "<TOP>" "schematic" nil "r") '
            'p=outfile("/tmp/inst_libs.txt" "w") '
            'foreach(inst cv~>instances fprintf(p "%s\\n" inst~>libName)) '
            'close(p) sprintf(nil "%d" length(cv~>instances)))')
```

Then on the shell: `ssh "$VB_REMOTE_HOST" "sort /tmp/inst_libs.txt | uniq -c"`. Expect:

```
   <stdcell_count> <STDCELL_LIB>     ← pure-reference stdcells
   <pin_count>     <TARGET_LIB>      ← top-level I/O pins (opin/ipin/iopin)
```

Where pin_count ≈ terminal count, and the local-lib cells are only `opin`/`ipin`/`iopin` — these are not duplicated stdcells, they are pin symbols ihdl creates for the top module's ports.

## What schematic placement you will (not) get

ihdl tiles instances onto a grid **in the order they appear in the verilog file**. Whether the result *looks* like a regular array depends entirely on the netlist's instance order:

- **Spatially-grouped netlists** (instances in placement-region order, same-cell-type clustered) → near-square grid (SIPO V8: 23k cells in 602 × 597 schematic units).
- **Naturally-ordered netlists** (no spatial clustering) → wide rectangle (V9Demo: 5.5k cells in 2573 × 1457).

This is **not** a parameter you can pass to ihdl — it's a property of the netlist. To force an array layout, either:

1. Sort instances by placement coordinates in the Innovus export script **before** `saveNetlist`, or
2. Post-process the schematic with a SKILL pass that grids the instances after import. The relative-offset pattern is:
   ```skill
   ; dbMoveFig transform = (dx, dy), NOT absolute target. Use ABSOLUTE - CURRENT.
   cur = inst~>xy
   dx = target_x - car(cur)
   dy = target_y - cadr(cur)
   dbMoveFig(inst cv list(list(dx dy) "R0"))
   ```
   Followed by `schCheck(cv) + dbSave(cv)`. Verified working for ~5.5k instances in one SKILL call.

Note that grid-reorganizing the **instances** without removing the **wires/labels** ihdl already drew leaves the wires anchored to the original (now-empty) positions — the schematic becomes visually broken. `cv~>shapes` for a 5.5k-instance schematic carries ~120k line/path/ellipse/label shapes. A complete grid re-layout means either (a) deleting all wire shapes and relying on connect-by-name only (legitimate — ihdl already uses connect-by-name internally; `instTerm~>net` carries the connectivity independent of wires), or (b) re-routing wires through the new grid (impractical at this scale).

## Decision table — which knobs for which export

Validated combinations from real Innovus exports against `scc011ums_uhd_rvt`:

| Design | Top module | True flat? | VPW/VNW in top? | power-net | Strip step needed | Pure-reference? |
|--------|-----------|------------|-----------------|-----------|-------------------|-----------------|
| SIPO V8 | `sipo_top_flat` (from `*_apr_flat.v`, not `*_apr.v`) | Yes | Yes (23705× each) | `VDDD`/`VSSS` | Yes | Yes |
| SIPO V9Demo | `sipo_v9demo_top` | Yes | Yes (5509× each) | `VDD`/`VSS` | Yes | Yes |
| PISO V4 | `piso_top_phy` | Yes | No | `VDD`/`VSS` | No | Yes |
| PISO V4Demo | `piso_v4demo_top` | Yes | No | `VDD`/`VSS` | No | Yes |

The empirical rule: **older / hand-written export scripts emit VPW/VNW in top instantiations; newer export scripts (PISO V4+) omit them**. Always run pre-flight check B before deciding.

## Failure modes seen in the field

| Symptom | Root cause | Fix |
|---------|-----------|-----|
| `instances=0` in schematic, view comes out as `functional` not `schematic` | Top module instantiates an undefined sub-module (e.g. `sipo_top u_core` when `sipo_top` was stripped). ihdl downgrades to `functional`. | You stripped the wrong file. Use the truly-flat netlist where the top instantiates leaf stdcells directly. |
| Target library fills with stdcell schematic/symbol/functional views (hundreds of leaf cells beside the top) | Top instantiation pins don't match ref-lib symbol terminals (e.g. VPW/VNW in netlist, not in symbol). ihdl creates local cellviews instead of pure-reference. | Apply step 4 (strip mismatched pins). Verify in `verilogIn.batch.log` — should see `VERILOGIN-126 Unable to find Verilog definition ... using library <STDCELL_LIB>`, not `VERILOGIN-372 Checked-in schematic <CELL>`. |
| `system() returned ''` and the wrapper exits non-zero, but the schematic eventually appears | ihdl detaches; daemon returns immediately. | Not an error. Poll `pgrep ihdl` to wait. Verify by tailing `verilogIn.batch.log` for `End of Logfile`. |
| `Warning: Terminal "VDD!" signal type mismatch: "power" in schematic, "signal" in symbol` | ihdl marked VDD/VSS as global power/ground in schematic, but ref-lib symbol terminals still have `sigType=signal`. | Cosmetic. Connectivity is correct (the `!` suffix denotes a global net). Ignore. |
| `add_power_labels.py` fails with `no instance has both VDD and VSS pins` | Stdcell **layout** cellviews in scc011ums_uhd_rvt have no terminal objects (`terms=nil`); power flows through M1 geometry without explicit pin terminals. | Skip this step on SMIC110/scc011ums_uhd_rvt-style libraries. If you need LVS-ready VDD/VSS labels on the top layout, drop them manually on the top-level power rails rather than via the per-instance lookup. |
| `dbMoveFig(inst cv list(list(x y) "R0"))` doesn't move the instance | `dbMoveFig` takes a transform whose translation component is a **relative offset**, not an absolute target. | Compute `dx = target_x - inst~>xy[0]`, `dy = target_y - inst~>xy[1]`, then pass `list(list(dx dy) "R0")`. |
| `*Error* setq/set: Variable t is protected` | Used `t` as a SKILL loop variable. | Rename to `tm`, `inst`, etc. |
| SKILL string formatting prints empty / SKILL list printout truncates over the bridge | Bridge string transport has length / quoting limits; complex nested `sprintf` with `%L` of long lists returns empty. | Write results to a remote file with `outfile`+`fprintf` and read them back via `ssh "$VB_REMOTE_HOST" "cat /tmp/..."`. |
