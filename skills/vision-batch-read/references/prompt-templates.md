# 读图 Prompt 模板

batch_read.py 默认用内置 prompt(返回 4 字段 JSON:caption/content/key_data/support)。
需要别的输出格式时,把下面的任一模板存成文件,用 `--prompt-from-file` 传入。

所有模板都要求**严格 JSON 输出**(模型不返回 markdown 代码块、不返回多余文字),
这样下游好解析。脚本内置 `extract_json` 容忍 ```json 包裹和尾逗号,但别依赖它。

---

## 模板 A:论文图(默认,4 字段)

适合 ljg-paper 阅读笔记的图件证据节。

```
你是 RF/集成电路论文的读图专家。仔细看这张图,返回严格 JSON(不要 markdown 代码块,不要多余文字),字段如下:

{
  "caption": "图的标题/编号,如 '图2-2 NFmin随手指宽度变化',看不出编号就概括图在讲什么",
  "content": "图展示了什么:2-3句,说清横纵轴、对象、趋势",
  "key_data": "关键数据/数值/结论,如 'NFmin在0.2mA/um最低','30GHz时MAG仅11dB'。无具体数据就写'无定量数据,定性为...'",
  "support": "这张图支撑论文哪个论点/机制,一句话。如 '支撑源极退化电感降低有效跨导'"
}

只返回 JSON 对象本身。
```

## 模板 B:通用图(领域无关)

```
仔细看这张图,返回严格 JSON:

{
  "caption": "图的标题或一句话概括",
  "content": "图里有什么:2-3句描述",
  "key_data": "关键数值/结论,无则写'无'",
  "support": "这张图可能用来论证什么,一句话"
}

只返回 JSON 对象本身。
```

## 模板 C:只取图注(最省 token)

适合先快速过一遍全部图,拿到图注做索引。

```
只看这张图,返回严格 JSON:

{"caption": "图的编号和标题,一句话。看不出编号就概括图在讲什么"}

只返回 JSON 对象本身。
```

## 模板 D:电路原理图专项

论文里大量电路原理图,需要识别拓扑和器件。

```
你是集成电路读图专家。看这张电路原理图,返回严格 JSON:

{
  "caption": "图编号和标题",
  "topology": "电路拓扑,如 '共源共栅Cascode','源极退化CS','电流复用共栅-共源'",
  "components": "关键器件:晶体管位置/数量、电感电容、变压器(线圈数/匝比)、关键电容",
  "mechanism": "这个电路的工作机制/设计意图,2句",
  "support": "支撑论文哪个技术点"
}

只返回 JSON 对象本身。
```

## 模板 E:仿真曲线图专项

S 参数/NF/增益等仿真曲线图。

```
你是 RF 仿真图读图专家。看这张曲线图,返回严格 JSON:

{
  "caption": "图编号和标题",
  "axes": "横轴/纵轴是什么,单位",
  "curves": "有几条曲线,分别代表什么(如 '虚线=常规共栅,实线=跨导增强')",
  "trend": "趋势:关键频点的值、极值、变化方向",
  "conclusion": "从图得出的结论,1句"
}

只返回 JSON 对象本身。
```

---

## 自定义 prompt 注意

1. **必须要求严格 JSON**,否则下游解析靠 `extract_json` 兜底,不稳。
2. **字段名固定且语义清晰**,下游代码按字段名取值。
3. **max_tokens 别太小**,4 字段大概要 200-300 token。模板 D/E 信息多,建议 400。
4. 模型读图质量取决于模型本身。`xopqwen35v35b` 经测试能识别 RF 曲线图趋势和电路拓扑,但对极精细数值(小数点后两位)可能读不准——关键数值以论文正文为准,图分析做辅助。
