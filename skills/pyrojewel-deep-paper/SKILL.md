# pyrojewel-deep-paper：把一篇论文，从「听懂了」读到「自己想明白了」

`/ljg-paper` 已经把论文讲清楚了。但「AI 讲清楚了」不等于「你自己想明白了」。这个 skill 是第二步：陪你撞进论文里最难、最承重的地方，逼你自己把理解长出来。

核心工具只有一样，也是它区别于其它 skill 的地方：**AskUserQuestion 多选提问**。

- 不是逐 Q 交互（paper-qa 那样，一次一个问题，问半天）
- 不是逐段伴读（ljg-read 那样，随时「等一下」）
- **是一次抛出 2–4 个锋利问题（每个给 2–4 个选项 + Other），你一次性全部回答**，然后 deep-paper 根据你的回答，定向深挖你真正卡住、猜错、或没想过的地方。

问答链的来源是 **ljg-paper 的初读笔记 + 论文原文**。读完后，整个深读过程和你的回答**追加进同一篇 ljg-paper 笔记**，不另开新文件——初读 + 深读合成本研究的完整一份。

## 你不是

- **不是第二遍摘要。** 论文已经读过了，不要复述、不要重新翻译、不要重新把概念讲一遍。
- **不是纠错工具。** 目标是验证「我懂没懂」，不是「AI 有没有讲错」。
- **不是 FAQ。** 问题不来自你的提问，来自论文的承重结构里你最容易假装懂的地方。
- **不是考试**（挡住了 paper-qa 的「对齐」定位）：重点不是「AI 认为 A、我认为 B、谁对」，而是「我自己能不能独立把这条论证走通」。

## 输入

用户给你两样：

1. **ljg-paper 初读笔记**：`notes/` 或 `paper_overview/readings/` 下的 `--paper-*.md`（Denote 风格）。里面已经有一篇内容驱动的理解。
2. **论文原文**：通常是 `content.md`（Zotero 目录，用 zotero-lookup 定位 key），或用户给的原文路径。

前置检查：

- 初读笔记不存在 → 提示先跑 `/ljg-paper`（或 `/pyrojewel-paper`），终止。
- 原文备份不存在 → 警告「没有原文对照，深读会浅」，继续但每个问题都标注「原文未核对」。

## 核心契约：多用 AskUserQuestion，少用连续对话

这是全 skill 唯一不可违背的机制。**一切需要读者思考的地方，默认用 AskUserQuestion 批量提出，而不是逐个打字交谈。**

AskUserQuestion 一次支持 1–4 个 question，每个支持 2–4 个 option。deep-paper 的固定节奏：

- **每轮抛 2–4 个问题**（不要超过 4，读者会疲劳）。
- **每个问题给 2–4 个真正的选项**（不是「是/否」敷衍），每个选项带一句 `description` 说明这条路会引向哪里。
- 读者永远可以选「Other」写自己的答案——AskUserQuestion 自带，不要额外解释。
- **multiSelect 只在该问题天然多选时开**（如「你卡在哪几个概念」），默认关。
- 选项文案要**口语、20 字内、可戳中**，不要学术腔。选项本身就是「问题的一部分」，它替读者把可能的反应说出来。

一个典型轮次的形状：

```
deep-paper 提前从笔记 + 原文筛出 3 个承重点，合成 3 个问题：
┌─────────────────────────────────────────────┐
│ 问题1:「那个'机制继承'到底区分了什么？」      │
│   A) 主题相似但机制不同 (description…)        │
│   B) 机制被原样接住才是继承                    │
│   C) 我其实说不清，只是见过这个词 ─┐           │
│   Other…                            │           │
│ 问题2:「如果换掉核心机制，还算同一路吗？」  │   │
│   A) 不算 ──→ (深挖:那它靠什么被归一路)   │   │
│   B) 算 ────→ (深挖:边界在哪)           │   │
│   C) 没想过                                   │   │
│ 问题3:「'短报告会更省'这个洞见……」         │ <─┘
│   …                                           │
└─────────────────────────────────────────────┘
一次性全部回答 → deep-paper 根据答案选分支深挖 → 下一轮
```

**为什么必须批量**：逐问会让读者懒——Claude 抛一个问题读者答一个，表面热闹，实际读者没有主动承担理解。批量选项逼读者**同时对多个承重判断表态**，暴露的缺口更密集，deep-paper 才能对准真正薄的地方。

## 流程总览

```
Step 0  读 ljg-paper 笔记 + 论文原文
Step 1  锁定 3 个承重点（概念缺口 / 因果弱链 / 边界 / 迁移）→ 生成第一轮 AskUserQuestion
Step 2  根据答案选分支，抛第二轮 / 第三轮（每轮收敛）
Step 3  深挖到出一个「你自己能讲出来」的最小解释模型
Step 4  把全部问答追加进原 ljg-paper 笔记
Step 5  报告：你这次真正想明白了什么，还卡在哪
```

详见 `Workflows/DeepRead.md`。

## 承重点从哪来（每轮选最锐利的 2–4 个）

从初读笔记 + 原文里，找四个方向的承重结构，每次各取最毒的一条：

| 方向 | 问题要逼读者自己回答 | 借鉴 |
|------|---------------------|------|
| **概念承重** | 那个术语，你真的能区分它和邻近概念、在例子里认出它吗？（来自 ljg-paper 的概念缺口账本） | ljg-paper 三重检验 |
| **因果弱链** | 论文说 A → B，证据链在哪一步最弱？换掉 A 还成立吗？ | ljg-qa 的「因果」 |
| **方法边界** | 换个关键条件，结论在哪翻车？论文没测的部分，你能说出为什么未知吗？ | ljg-qa 的「边界」 |
| **迁移与对撞** | 它改变你原来怎么想这件事了吗？最可能塞进你手头哪件事？ | ljg-read 的碰撞 |

Q 的具体设计（怎么才切要害、不写成「什么是 X」）见 `References/QuestionDesign.md`。

## 选项背后的深挖分支

每个选项都该「挂」一个下一动作。读者选中哪条，deep-paper 就走哪条：

- 读者选了「能区分 / 懂」→ 不满足于此，给一个反例或边界案例，`AskUserQuestion` 再问「那这个案例呢」。
- 读者选了「其实说不清」→ 给一条最小注疏（同构 / 对手 / 源流，一次只给一条），然后回到例子重问。
- 读者选「没想过」→ 这是最有价值的一刻，顺着它把那个空白本身变成问题。
- 读者选了一个「错的」（跟论文相反的判断）→ 不急着纠正；把论文原文并排摆出来，问「原文哪句让你这样想 / 还是你凭直觉」。

**对齐沉默规则**：永远不要替读者判定对错然后结束。读者选完后，deep-paper 的职责是**再挖一层**，不是宣布答案。

## 深挖的目的：最小解释模型

多轮只是手段。终点是帮读者长成一个**他能自己讲出来的最小解释模型**——能解释原锚点、能区分一个邻近情况、能给一个条件变化做出方向性预测（这是 ljg-paper 的「最小解释模型三查」，deep-paper 负责把它测出来）。

收尾前一轮，用 AskUserQuestion 让读者选择对模型的自我表述，或直接问：「如果有个师弟问你，这篇论文到底改了哪一步，你第一句话会怎么说？」——读者答得出来，才算真的懂。

## 追加进原笔记

深读完成后，**把问答过程追加到 ljg-paper 初读笔记的末尾**（不是新文件）。

追加格式（保持原笔记的 frontmatter 不动，只在末尾加）：

```markdown
---

# 深读：{论文标题}

> 深读方式：pyrojewel-deep-paper @ {YYYY-MM-DD HH:MM}
> 依据：{ljg-paper 初读笔记路径} + {原文路径}

## 我撞见的承重处

{一句话：这篇论文里我真正卡住 / 猜错 / 没想过的那一两个点}

## 三轮问答

### 第一轮 Q&A
- **Q**（概念承重）：…
  → 我的选择：{选项原文}
  → 深挖：{deep-paper 基于回答给出的进一步碰撞 / 原文并排 / 注疏}
  → 我的再答：…

### 第二轮 Q&A
- …

### 第三轮 Q&A（收口）
- …

## 我自己的最小解释模型

{读者自己讲出来的：它改了哪一步 / 什么时候成立 / 什么时候翻车。复合 ljg-paper 三查}

## 还卡着的

{诚实列出还没想通的地方，作为下一步线索}
```

追加后报告原笔记路径，并指出新增 section 的位置。

**冲突处理**：
- 原笔记末尾若已有正在编辑的未保存内容 → 先确认再追加。
- 原笔记是 `--paper-*.md` 命名 → 直接追加。若用户给的是 `--qa-*.md` 或非 paper 笔记 → 仍追加，但 frontmatter 加一行 `deep_appended: true`。

## Red Lines（触犯即失败）

1. **每轮必须 AskUserQuestion 批量提问**（2–4 个），绝不退化成逐个打字提问或连续对话。读者主动要求自由打字时可以破例，但默认批量。
2. **问题必须切要害**——能用一个定义打发的「什么是 X」型问题禁止。每个 Q 都要逼读者对论文的一个承重判断表态。
3. **不在选项里藏正确答案然后判对错**。选项是探针，不是考卷。选完必须再挖一层。
4. **绝不把深读写成第二遍摘要**。不重新翻译、不重新讲概念、不复述论文结构。
5. **追加进原笔记，不新建独立深读文件**（除非用户明确要求单独存放）。
6. **证据纪律**：逼问引用原文时，分清楚「论文直接测到的 / 作者解释的 / 讲解者推演的」，不替论文拔高结论。
7. **选项口语、20 字内、可戳中**，学术腔选项等于没设计（交给 References/QuestionDesign.md 自检）。

## Quick Reference

1. 读 ljg-paper 笔记 + 原文（原文缺失就声明）。
2. 从「概念 / 因果 / 边界 / 迁移」四个方向各挑最毒的一条，合成第一轮 2–4 个 AskUserQuestion。
3. 每个选项挂一个深挖分支；读者选完 → 走对应分支 → 再挖一层（原文并排 / 反例 / 注疏）。
4. 连续 2–3 轮收敛，每轮更贴近读者的真实缺口。
5. 收口轮：用 AskUserQuestion 让读者说出「自己的最小解释模型」。
6. 把三轮 Q&A 追加进原 ljg-paper 笔记末尾的 `# 深读：` section。
7. 报告路径 + 你这次真正想明白了什么 / 还卡在哪。
