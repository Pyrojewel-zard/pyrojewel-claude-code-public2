# Question Design：把承重点变成「一次性批量回答」的锋利问题

本文回答一个问题：一篇论文的深读，怎么设计成 1–4 个一组、每个 2–4 个选项、读者一次性答完的 AskUserQuestion。

核心立场：**选项就是问题的一部分**。问题负责把读者摁在论文的一个承重判断上；选项替读者把可能的反应说出来，并各自通向一条深挖分支。

## 第一步：从 ljg-paper 笔记里找承重点（不是从目录找）

ljg-paper 笔记里已经标了论文改的是 `x / R / f / E` 中的哪一项、哪些是承重概念、证据链在哪。先扫这些，不要重新泛读论文。

每个承重点应当命中下面至少一类。一篇好深读，四类至少覆盖两类（通常 2–4 轮就够）：

| 方向 | 你要逼读者自己判断什么 | 直觉信号「这是个承重点」 |
|------|----------------------|------------------------|
| **概念承重** | 这个术语区分了什么、不是什么、在例子里认不认得出来 | 读者能背定义、能翻译、能举相似例子，但换一个反例就懵——「假熟悉」 |
| **因果弱链** | A → B 这条论证在哪一步最容易被反驳 | 论文自己都没测的那步；作者用「较稳地显示」而不是「证明」的地方 |
| **方法边界** | 换个关键条件，结论在哪翻车 | 论文的适用范围紧跟在某个前提；读者却把结论当普适真理 |
| **迁移与对撞** | 它改变你原来怎么想这件事了吗 | 读者看完只记得「学到了一个概念」，说不出自己原来的看法哪里变了 |

## 第二步：把承重点压成问题（Q 的规矩）

沿用 ljg-qa 的禁忌，deep-paper 只有更严：

- ❌「什么是 X？」——一句定义能打发，没承重。
- ❌「X 有几步？」——问目录，不是问思想。
- ❌「X 重要吗？」——答案预设。
- ❌「我们该如何看待 X？」——学术腔，读者不用表态。
- ❌「X 的优缺点？」——八股。

deep-paper 的问题长这样（逼表态、可戳中、20 字内）：

| 方向 | 好问题 | 为什么能承重 |
|------|-------|------------|
| 概念 | 「'机制继承'到底区分什么？」 | 逼读者说清它与「主题相似」差在哪 |
| 概念 | 「'早停'解决的是哪一步，不是哪一步？」 | 逼读者不把「想得更久」和「知道何时停」混成一件事 |
| 因果 | 「链式推理能涌现，证据链最弱在哪？」 | 逼读者找到作者没测的那步 |
| 因果 | 「换成迭代，结果还成立吗？」 | 逼读者想「什么被这个机制撑住」 |
| 边界 | 「什么时候工具反而添乱？」 | 逼读者说出失效条件，而不是复述结论 |
| 边界 | 「搬到新楼以后，谁重新接管？」 | 逼读者想「这个机制在什么情境下被另一机制取代」 |
| 迁移 | 「它最可能塞进你手头哪件事？」 | 逼读者从「听懂了」到「连到自己的活」 |
| 对撞 | 「它有没有改变你原来怎么想这件事？」 | 对撞读者脑中已有的默认框架 |

**优先级**：如果只能挑 2–4 个问，优先挑读者最可能**假装懂**的（概念假熟悉 > 因果弱链 > 普适化边界 > 迁移）。「AI 讲清楚了你却没想过」通常是认知增量最大的地方。

## 第三步：每个 Q 配 2–4 个「挂分支」的选项

选项不是干扰项，是**读者可能所处的状态**。每个选项必须在语义上可区分，且各自指向下一步深挖。一次交互里 reader 多选才开 multiSelect，其余默认单选。

常用选项空间（按读者状态设计）：

```
✓ 状态型：读者自评现在处在哪一步
   A) 我能说清它区分什么    B) 我能认出但说不清    C) 其实只是见过这个词    Other…

✓ 判断型：逼读者对论文的一个承重判断表态（选项 = 可能的立场）
   A) 换掉核心机制就算另一路   B) 算，只要问题一样   C) 我没想过边界   Other…

✓ 迁移型：问读者想把论文连到哪里
   A) 塞进我正在做的 X    B) 只能当知识了解    C) 我暂时看不出用在哪   Other…
```

**每个选项都要 `description`**（AskUserQuestion 的选项描述字段），写「选这条路会怎样」——让读者选之前知道后面碰到什么：

```
A) 我能说清「机制继承」区分什么
   description: 那你来一句：它和「主题相似」差在哪？深挖会立刻验证
B) 能认出，但说不清
   description: 我们回到两份方案的例子，把它和邻近概念摆开
C) 只是见过这个词
   description: 先给一条最小注疏，再用原例重跑一次
```

### 反例选项（必须有）

每个承重点至少留一个「反例 / 边界 / 没想过」的出口——这是 deep-paper 挖出真缺口的手段。读者选它时，往往就是这次深读最重要的收获。

## 第四步：选项挂分支（选完必须再挖，禁止「选对就算过」）

每个选项背后最少挂一个动作，读者选完就走。模型：

```
选项选 X → 深挖动作 → AskUserQuestion 再抛下一轮 / 或原文并排
```

常见分支动作：

| 读者状态 | deep-paper 动作 |
|---------|----------------|
| 说懂 | 抛一个**反例或边界案例**：那这个 case 呢？（别信「懂了」） |
| 说不清 | 给**一条最小注疏**（同构 / 对手 / 源流，一次只给一条）→ 回原例重问 |
| 没想过 | 把这个「空白」本身变成下一个问题（通常就是最大认知增量） |
| 持相反判断 | **原文并排**（中英并列 / 原句引用），问「是原文哪句让你这样想，还是直觉」 |
| 迁移到具体事 | 追问「具体哪个输入、哪个条件不一样」——落成可做的一件事 |

**对齐沉默规则**：deep-paper 永远不说「正确答案是 A，你错了」。选项是探针；选完的使命是让读者看见自己走到了哪、还差哪一步，不是判分。

## 第五步：轮次节奏（2–4 轮收敛）

- **第 1 轮**：3–4 个问题，覆盖 2–3 个方向，先摸清读者整体站在哪。
- **第 2 轮**：从第 1 轮答案里挑最薄的那 1–2 个点，抛 2–3 个问题深挖。
- **第 3 轮（收口）**：1 个问题，逼读者讲出「自己的最小解释模型」——见 `SKILL.md` 的收口。

每轮问题数**递减**，深度**递增**。不要每轮都抛 4 个无关问题。

## 自检清单（提交前逐条过）

- [ ] 每个 Q 逼读者对论文**一个承重判断**表态，不是复述论文。
- [ ] 没有「什么是 X」「X 有几步」「X 重要吗」。
- [ ] 每轮 2–4 个 Q；每个 Q 有 2–4 个可区分、口语、20 字内的选项。
- [ ] 每个选项带 `description`，说明会引向哪。
- [ ] 至少留一个「反例 / 没想过 / 说不清」出口。
- [ ] 每个选项挂了深挖分支，选完一定再挖一层。
- [ ] 轮次递减收敛，不是每轮等量散问。
- [ ] 问题来源是初读笔记 + 原文的承重结构，不重新泛读论文。
- [ ] 引用的论文判断没有拔高证据。
