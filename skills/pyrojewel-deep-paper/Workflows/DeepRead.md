# DeepRead Workflow：把一篇论文深读到「读者自己讲得出来」

执行总原则见 `SKILL.md`。本文是 Step 0–5 的可执行细节。

## Step 0：读 ljg-paper 初读笔记 + 论文原文

1. 定位初读笔记：`notes/` 或 `paper_overview/readings/` 下的 `--paper-*.md`（若只有 pyrojewel-paper 的 `--paper-*.md` 也一样处理）。
2. 定位原文：优先走 zotero-lookup 得到 `{attachmentKey}/content.md`；用户给了原文路径直接用。
3. 读完后在脑中（或纸上）标出：
   - 论文主要改的是 `R / f / E / x` 哪一项（ljg-paper 的后台标记）；
   - 哪些是承重概念（ljg-paper 概念缺口账本里「拿掉会断」的）；
   - 因果链上最弱、或论文自己没测的那一步；
   - 结论的适用范围（哪些前提撑着它）。

原文缺失 → 明确告诉用户「本轮深读没有原文对照，引用的判断可能不够深」，继续但每个涉及原文的判断标注「未核对原文」。

## Step 1：锁定承重点，生成第一轮 AskUserQuestion

按 `References/QuestionDesign.md`，从四个方向（概念 / 因果 / 边界 / 迁移）各挑最毒的一条，合成 **3–4 个问题 + 每个 2–4 个选项**。

拿到 AskUserQuestion 的 answers（用户可能全答、部分答、或选择回答其中环境不允许的部分——接受即可）。

## Step 2：根据答案选分支，抛第二轮 / 第三轮

对用户每个选择，走到对应深挖分支（`QuestionDesign.md` 的分支表）：

- 选「懂」→ 抛反例 / 边界案例：「那这个 case 呢？」
- 选「说不清」→ 给一条最小注疏（同构 / 对手 / 源流，一次一条）→ 回原例重问。
- 选「没想过」→ 把这个空白本身变成下一个问题。
- 持相反判断 → 原文并排，问「是原文哪句让你这样想，还是直觉」。
- 迁移到具体事 → 追问「具体哪个输入、哪个条件不一样」，落成一件可做的事。

每轮从上一轮选出**最薄的那 1–2 个点**深挖，抛 2–3 个新问题。轮次递减、深度递增。通常 2–3 轮收敛；读者有明显缺口时加一轮，不设上限（但担心疲劳就收）。

## Step 3：收口——逼出「读者自己的最小解释模型」

最后一轮只问一个问题（AskUserQuestion 或自由打字均可，优先 AskUserQuestion）：「如果有个师弟问你，这篇论文到底改了哪一步，你第一句话会怎么说？」

验证读者答案是否满足 ljg-paper 的「最小解释模型三查」：

1. 能解释贯穿论文的**原锚点**（不只是换词复述）；
2. 能区分一个**邻近情况**（看似相同的案例为何不同）；
3. 能对一个**条件变化**给出方向性预测（某概念变强/变弱/缺席会先观察到什么）。

三查有一项过不了 → 回 Step 2 深挖那一个点，再回来收口。

## Step 4：追加进原 ljg-paper 笔记

把三轮问答**追加到初读笔记末尾**，格式见 `SKILL.md` 的「追加进原笔记」。要点：

- 不动原 frontmatter；在文末加 `---` 分隔 + `# 深读：{标题}`。
- 完整记录每轮：问题原文 / 用户选的选项 / deep-paper 的深挖 / 用户再答。
- 用户打字补充的自由回答也保留（标记「自由回答」）。
- 收口的最小解释模型单独成节。
- 「还卡着的」如实写，不假装全懂。

冲突处理：
- 原笔记末尾有未保存的用户编辑 → 先确认再追加。
- 用户给的笔记不是 paper 笔记 → 照常追加，frontmatter 加 `deep_appended: true`。
- 用户明确要求单独存放 → 例外地新建 `{ts}--deep-{short-title}.md`，并在 SKILL.md 的红线里破例说明。

## Step 5：报告

告诉用户：
1. 原笔记路径 + 新增 `# 深读：` section 的位置。
2. 一句总结：这次你真正想明白了什么（哪一步从「听说过」变成「自己能讲」）。
3. 一句诚实剩留：还卡在哪（给下一步线索，不硬塞书单）。

## 中断处理

- 用户中途说「够了/停」→ 把已完成的部分追加进笔记，报告「只深读到第 N 轮」。
- AskUserQuestion 某题用户不答 → 跳过该题，不纠缠。
- 用户想脱离选项自由聊 → 允许切到自由对话（红线里已声明读者主动要求时可破例），但下一轮仍拉回 AskUserQuestion。
